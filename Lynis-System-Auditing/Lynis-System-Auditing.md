# System Auditing & Hardening using Lynis

Lynis is an open-source security auditing tool for UNIX-based systems such as Linux, macOS, and BSD. It performs a detailed security audit, identifies configuration weaknesses, and provides hardening suggestions.

## Requirements

- Kali Linux virtual machine — attacker/testing machine
- Metasploitable 2 virtual machine — optional target for remote auditing
- Both machines connected to the same isolated lab network
- SSH access available for remote auditing

## Objectives

- Install and use Lynis on Kali Linux
- Perform a local system security audit
- Understand remote auditing over SSH
- Identify security warnings and hardening suggestions
- Review installed software, services, filesystems, and security configurations
- Understand the logs and reports generated by Lynis

# Lynis Basics

## 1. Installing Lynis

Lynis can be installed on Kali Linux using APT.

**Command:**
```bash
sudo apt install lynis
```

**Command breakdown:**

| Part | Meaning |
|---|---|
| `sudo` | Run the command with administrative privileges |
| `apt` | Debian/Kali package manager |
| `install` | Install a package |
| `lynis` | Lynis package |

---

## 2. Basic Usage and Help

Run Lynis without arguments to display its available commands and options.

**Command:**
```bash
lynis
```

Useful commands include:

```bash
lynis audit system
lynis audit system remote <host>
lynis show
lynis update info
```

- `lynis audit system` — audit the local system
- `lynis audit system remote <host>` — audit a remote system through SSH
- `lynis show` — display available information
- `lynis update info` — display update information

# Lynis in Action

## 3. Local System Audit

A local audit checks the security configuration of the machine on which Lynis is running.

**Command:**
```bash
lynis audit system
```

Lynis examines areas such as:

- Operating system and kernel
- Authentication configuration
- Installed software
- Running services
- Firewalls
- Filesystems and mount options
- Network configuration
- System hardening settings

> **Important:** Run Lynis with appropriate privileges when a complete audit is required. A non-privileged scan skips tests that require administrative access.

---

## 4. Non-Privileged Mode

When Lynis is executed without sufficient privileges, some security tests are skipped.

Examples include checks for:

- Bootloader configuration
- Group and shadow files
- Password hashing methods
- Sudo configuration permissions
- Other privileged system settings

This is why administrative privileges are important when performing a complete system audit.

---

## 5. Software and Service Enumeration

Lynis examines installed software and services and checks their security configuration.

### Firewall

Example checks may include:

```text
Checking iptables kernel module: [ NOT FOUND ]
Checking host based firewall:    [ NOT ACTIVE ]
```

These results indicate what Lynis found on the audited system; they are not automatically proof that the entire host is insecure.

### Web Server

Lynis can detect web-server software such as Apache and inspect its configuration.

Example findings:

```text
Checking Apache binary: [ FOUND ]
Configuration file: /etc/apache2/apache2.conf
```

It can also inspect enabled modules and relevant configuration settings.

### Shells

Lynis checks the shells configured on the system, including:

```text
/etc/shells
```

It may also check session timeout settings and default umask configuration.

---

## 6. Filesystems and Storage

Lynis checks filesystem mount points and security-related mount options.

Examples:

- `/home`
- `/tmp`
- `/var`
- `/dev/shm`
- Swap configuration

It can also check:

- Sticky-bit configuration
- `nodev`
- `nosuid`
- `noexec`
- Read-only mount options
- Temporary files
- Storage-related drivers

Example result:

```text
Checking /home mount point: [ SUGGESTION ]
Checking /tmp mount point:  [ OK ]
Checking /var mount point:  [ OK ]
```

---

## 7. System Services and Kernel

Lynis audits kernel settings and enabled system services.

Example areas:

- Default runlevel
- CPU security features such as NX/PAE
- Kernel version
- Enabled systemd services
- Service security exposure

Lynis can use systemd security analysis to identify services that may require additional hardening.

# Remote Auditing

Lynis can also audit a remote UNIX/Linux system through SSH.

In this lab, the remote target was:

```text
192.168.37.130
```

### 8. Remote Audit

**Command:**
```bash
lynis audit system remote 192.168.37.130
```

Lynis automates the remote-audit process by preparing the Lynis files, transferring them to the target, executing the audit through SSH, retrieving the results, and cleaning up temporary files.

### What happens internally

**Step 1 — Create the Lynis archive**

```bash
mkdir -p ./files && cd .. && tar czf ./files/lynis-remote.tar.gz --exclude=files/lynis-remote.tar.gz ./lynis && cd lynis
```

**Step 2 — Transfer the archive**

```bash
scp -q ./files/lynis-remote.tar.gz 192.168.37.130:~/tmp-lynis-remote.tgz
```

**Step 3 — Execute the audit through SSH**

```bash
ssh 192.168.37.130 "mkdir -p ~/tmp-lynis && cd ~/tmp-lynis && tar xzf ../tmp-lynis-remote.tgz && rm ../tmp-lynis-remote.tgz && cd lynis && ./lynis audit system"
```

**Step 4 — Remove the temporary directory**

```bash
ssh 192.168.37.130 "rm -rf ~/tmp-lynis"
```

**Step 5 — Retrieve the audit results**

```bash
scp -q 192.168.37.130:/tmp/lynis.log ./files/192.168.37.130-lynis.log
scp -q 192.168.37.130:/tmp/lynis-report.dat ./files/192.168.37.130-lynis-report.dat
```

**Step 6 — Remove temporary result files**

```bash
ssh 192.168.37.130 "rm /tmp/lynis.log /tmp/lynis-report.dat"
```

# Commands I Typed vs. Automated Commands

## Commands typed manually

| Command | Purpose |
|---|---|
| `nmap --script http-malware-host 192.168.37.130` | Scanned the target using the specified Nmap NSE script |
| `linus` | Typo — command not found |
| `lynix` | Typo — command not found |
| `lynis` | Opened Lynis / displayed its usage |
| `sudo apt install lynis` | Installed Lynis |
| `lynis audit system remote 192.168.37.130` | Started the remote audit |
| `lynis audit system` | Started the local audit |

## Commands executed automatically during the audit

Lynis performs many checks by executing system commands. Examples include:

```bash
cat /etc/os-release
uname -r
systemctl list-unit-files
iptables -L
ls /etc/apache2/mods-enabled/
cat /etc/shells
mount
rpcbind -p
systemd-analyze security
```

These commands were part of Lynis's automated auditing process rather than commands manually typed by the user.

# Understanding Lynis Results

Lynis commonly reports findings using statuses such as:

| Status | Meaning |
|---|---|
| `[ OK ]` | The check passed or the expected configuration was found |
| `[ SUGGESTION ]` | Lynis recommends reviewing or improving the configuration |
| `[ WARNING ]` | Lynis identified an issue that requires attention |
| `[ FOUND ]` | The requested software, file, or feature was detected |
| `[ NOT FOUND ]` | The requested item was not detected |
| `[ NOT ACTIVE ]` | The feature/service was found but is not active |

A suggestion is not necessarily a vulnerability. Lynis provides recommendations that should be reviewed in the context of the system's purpose.

# Reports and Logs

Lynis produces audit information that can be reviewed after the scan.

Common files include:

```text
/var/log/lynis.log
/var/log/lynis-report.dat
```

The exact location can depend on how Lynis is installed and executed.

The report can be used to review:

- Warnings
- Suggestions
- Security checks
- Test results
- System information
- Hardening opportunities

---

# Key Takeaways

1. **Lynis is a security auditing tool** used to assess UNIX/Linux systems.
2. **Local audits** inspect the machine where Lynis is executed.
3. **Remote audits** can be performed over SSH against a compatible remote system.
4. **Root/administrative privileges** allow Lynis to perform additional security checks.
5. **Suggestions and warnings should be reviewed**, rather than treating every suggestion as a vulnerability.
6. Lynis can inspect **software, services, authentication, filesystems, kernel settings, and other security configurations**.
7. Audit logs and reports provide useful information for **system hardening and security review**.
